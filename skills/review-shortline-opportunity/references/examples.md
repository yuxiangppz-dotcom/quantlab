# 合成审阅案例：主 agent 雪球日线模式

以下均为离线说明，不是实际推荐，也不证明本人已经访问雪球。真实运行必须由主 agent 实际浏览，示例 ID、URL、主体和日期应替换为本次访问与程序输入中的真实记录。

## 正常：缩量回调后的确认

程序给出 B 路线通过、持续方向、资格允许 priority、完整资金与完整龙虎榜查询未上榜、有效冻结区间。假设主 agent 已真实打开该证券雪球日K页，核对代码、可见回调／确认日期、行情截止与复权口径；记录 `view=daily`、含实际信号日的 `visible_dates`、`status=complete`、不早于准备cutoff的 `observed_at`，日线改善及仍临近压力的反证使用 `daily_visual.fact_ids` 绑定本股事实。资金轻微流出但没有程序降级，同行只有一个同样合格对象。

可以有条件保留 priority：引用过程事实、资金口径、未上榜中性以及真实日线浏览记录；比较唯一合格同行，解释回调流出和修复之间是否仍有冲突。最强反证不能只写“短线有风险”，应指出上方压力与修复不持续的具体可能。不能虚构第二个同行、资金身份或收益概率；不把日线改善称分时承接确认。

## 冲突：突破与严重披露净卖出

程序给出 A 路线通过，但同范围已验证的龙虎榜净额 -4000 万元、成交额 5 亿元，规则已经输出 exclude。假设本次实际雪球日线浏览显示价格暂时稳定，新闻叙述积极。

继续 reject/excluded，分别引用突破事实、严重卖出规则和真实浏览记录；日线稳价不证明卖压消失。可以记录未来重新研究条件，不能引用利好或“机构洗盘”解除本次限制，不改用其他统计区间抵消该事件。

## 网页受阻：未真正看到日K与资金缺数

主 agent 打开雪球证券页并核对代码，但只看到日K按钮或摘要，canvas没有可读走势／日期；记录真实URL、不早于准备cutoff的浏览时间与可见日期缺口。资金一日窗口完整、三／五日缺数，龙虎榜来源delayed。程序日线形态通过，但资格上限watch。

最多watch，`daily_review.view=daily`、`status=partial`、`visible_dates=[]`、`quality=unknown`，`daily_visual.support=""`、`effect=unknown`；整个页面不可取得才记unavailable。明确没有实际复核日K，不能推断承接；保留已知一日资金与其他未知。不能把源失败写成未上榜、缺数填零或用摘要代替可见走势。按固定预算结束浏览，定向补证最多每股两次；仍受阻就保持未知，不调用外部模型补造结果。外层哈希绑定实际research；此案例只验证设计说明，不能当作真实网页登录受阻的测试回执。
