# QuantLab 主线与历史能力的边界

## 当前主线

目标是可维护的个人日频 ML 研究和模拟系统。清晰意味着职责与入口明确；完整意味着在所声明
范围内从数据到决策、账本和评价闭环；可信意味着拒绝未知事实、时序可核验、失败不污染恢复；
可持续意味着日常增量处理、幂等、可观察、可恢复，并有真实环境运行验收。

| 层 | 输入与输出 | 主责 |
|---|---|---|
| 数据 | 本地来源 → Canonical/来源凭据 → 研究快照 | 历史身份、时点、单位、缺失和版本 |
| 研究 | 研究快照 → 成熟标签 → 滚动模型/样本外分数 | 模型比较、验证、实验记录 |
| 组合 | 分数 + 实际持仓 → 目标 + 股数订单 | 缓冲换仓、现金和集中度约束 |
| 账户 | 封存订单 + 后续市场证据 → 成交、持仓和现金 | 费用、可交易性、公司行动、连续账本 |
| 运行 | 每日快照 + 启用模型 → 当日结算和下一日决策 | 连续日期、幂等、模型有效期、暂停、状态 |
| 评价 | 信号与账户结果 + 同期基准 → 可追溯报告 | IC、净值、成本、换手、风险及缺失覆盖 |

历史回测和每日模拟共用 ml/replay.py 的 plan_orders、settle_plan，以及已有 quantity 内核。
每日服务不重新构造已经封存的历史目标，模拟账本不写 personal 真实账户。

## 入口收敛

- 新实验与新日常任务：`quantlab pipeline --project ...`。编排 data 与现有 ml 内核；UI 默认 ML 工作台。
- 完整数据与运行契约见 [项目主线手册](project_pipeline_zh.md)，ml 命令是高级底层接口。
- 数据管理和 personal 账户能力继续独立，不能把模拟净值当成用户资产。
- 老 `daily`、顶层 `shadow`、固定年度 Alpha158、周频/扩展实验：历史复现入口。
- 原 README 的阶段进度和详细旧命令已集中到 legacy_readme_reference.md。

未为了目录好看而移动所有冻结模块：ml/history.py 仍使用 alpha158_native 的特征契约、
alpha158_rolling_data 的分区校验、round2_dataset 的封存读取；旧实验的 hash/依赖也可能绑定原路径。
因此保留这些共享能力，停止向冻结实验堆叠新产品逻辑。后续只有在确认调用图、历史兼容和测试后，
才逐项抽离或删除具体实现。缓存清理不包括唯一数据、模型、账户或证据。

## 与成熟公开项目对齐的部分

- [Qlib workflow](https://qlib.readthedocs.io/en/latest/component/workflow.html)：研究与模型产物可复现。
- [Qlib online serving](https://qlib.readthedocs.io/en/latest/component/online.html)：训练、模型启用、每日信号分离。
- [LEAN 时间模型](https://www.quantconnect.com/docs/v2/writing-algorithms/key-concepts/time-modeling/timeslices)：信息可用时点与决策顺序。

这里采用相应职责划分和时间语义，不复制整套框架，也不把公开项目称为没有缺陷的认证标准。
默认简单缓冲组合是个人开发的可解释基线；复杂优化器、深度模型不作为闭环完成的前置条件。

## 仍需本地完成

1. 数据及真实来源时点、股票池、行业、单位的验证。
2. 费用、规则、公司行动、特殊清算的历史适配与样本对账。
3. 内存/容量/成本和真实样本外研究；结果差时可以拒绝模型。
4. 已实现每日适配器的真实样本验收、WSL 调度部署、日志告警和备份恢复演练，以及实际前向观察天数。

合成测试通过仅代表覆盖的工程行为符合预期，不认证供应商事实、模拟可成交性或策略收益。
