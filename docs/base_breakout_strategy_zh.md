# 价量筑底突破策略

## 策略目标

该策略识别“经历过明显下跌后，抛压减弱、价格结构企稳，并可能进入启动阶段”的股票。日线数据无法确认交易者身份，所以代码不会声称识别真实主力账户；“主力筑底”在这里严格表示可复核的价量形态。

这是一个完整的研究策略入口，而不是单项公式组件。它从本地 Canonical 日线和复权因子生成特征，输出状态、候选排名、目标权重以及 1/5/10/20 个交易日的信号收益诊断。

## 治理状态

仓库策略注册表将本策略记录为 `RESEARCHED` 候选，版本身份为
`s5b_frozen`。该状态只确认冻结实现、配置、文档和合成测试已经存在；
它不表示历史经济回测已完成，也不表示已经进入 Forward Shadow、通过用户
评审或获得任何下单权限。

## 状态判断

策略先要求过去 120 个市场交易日数据连续完整，并确认此前相对 120 日高点至少回撤 20%。随后分三层判断：

1. **失败**：最近十日跌幅过快、最大回撤过大、新低下穿超过 3%，或波动继续扩张。这里会把真正的下跌延续排除掉。
2. **筑底中**：允许最近十日继续出现少量 60 日新低；只要不是深度下穿，就不会自动失败。但若新低过于频繁、没有在三日内收回、从低点反弹不足、仍在 MA20 下方或 MA20 继续下行，状态仍是筑底中，不进入候选组合。
3. **筑底就绪 / 放量突破**：价格已回到区间中上部、站回 MA20 且均线不再下行时进入筑底就绪；进一步突破前 20 日高点并满足量能确认后，升级为放量突破。

因此，“创新低”本身不是否决项。策略真正否决的是**新低很深、跌得很快、波动扩大或迟迟收不回来**。

## 窗口与持有期

120/60/20/10/5 日窗口只负责描述历史形态，不等于必须持有相同天数。配置中的 `signal_interval_sessions` 默认是 1，表示每天都可以重新产生一组研究信号；改成 5 或 10 只会降低信号/调仓频率，不会修改筑底定义，也不会强制锁仓。

`evaluation_horizons` 默认同时报告 1、5、10、20 日信号日至未来收盘收益，目的是观察信号在哪个周期有效。它们不是锁仓要求，也不是实际可成交收益。风险账本接入后，每个信号日都可改变目标；目标在两个信号日之间保持不变，但这不是锁仓。默认每日出信号时，股票次日不再入选即可产生退出目标，委托再按账本的 T+1 时间线执行。因此策略允许短至一个交易日的持有变化，同时仍受可卖数量、停牌和涨跌停等研究约束。

## 运行方式

```bash
uv run python scripts/run_base_breakout_strategy.py \
  --start 2023-01-01 \
  --end 2024-12-31
```

输出位于 `data/experiments/price_volume_base_breakout/<run_id>/`：

- `signals.csv`：每日股票状态、失败原因、候选排名、目标权重和剩余现金；
- `diagnostics.csv`：不同状态在各观察期的收盘到收盘收益统计；
- `summary.json`：配置、输入指纹、Git 提交和权限边界。

## 当前边界

`materialize_base_breakout_targets` 会严格校验策略身份、研究权限标记、入选状态、目标权重、现金权重和日期，然后把信号转换为 `TargetPortfolio`。`run_base_breakout_risk_ledger` 已把这些目标接入现有风险账本：每日先执行前一日意图并计费、按原始收盘价估值，再运行既有市场风控、缩放 S5-B 目标并生成下一交易日意图。风险规则本身没有被修改。

这条链路会模拟 T+1、数量网格、费用、容量、停牌、涨跌停以及逐日风险上限；缺少任何必要证据时会保留最后一个完整检查点并停止。它仍明确属于假设研究账本：代码不会认证本地历史数据、费用权威、公司行动完整性或真实成交，因此在这些输入经过本地验证前，结果不能称为真实年化收益或可执行订单。
