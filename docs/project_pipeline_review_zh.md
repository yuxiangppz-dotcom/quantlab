## 审查结论与已修复问题

| 发现 | 处理 |
|---|---|
| ML 入口之前的数据下载/特征准备仍依赖手工拼接 | 新 pipeline 配置贯穿 TuShare、Canonical、Alpha158、训练、交易证据和每日账户 |
| 下载无统一原始来源记录与有限重试 | ObservedClient 记录实际响应与获取时间、节流、有限重试、脱敏错误；日频响应上限保护 |
| 文件存在被当作同步完成，半写入难以恢复 | 全日七类数据先验证并暂存，再提交；完成回执绑定哈希，待提交事务可恢复，旧分区需明确接管 |
| SSE/SZSE 缺日/冲突可能被合并隐藏 | 新同步要求请求区间逐日一致且完整；不从缺行推断休市 |
| 增量更新与历史更新对上市前占位行处理不一致 | 复用同一已知上市日过滤函数，不以缺 pre_close 擅自过滤 |
| 历史/每日特征容易分叉，多年处理可能超内存 | 固定 native Alpha158 单一计算函数、63 日分批和预算限制，真实 Qlib 一致性测试 |
| 时间戳单位和窗口来源传播容易出错 | 按真实带时区时间取窗口最大值；不得把 pandas 微秒整数误当纳秒；收盘数据不得早于收盘可知 |
| 退出股票池的标签端点可能丢失 | 价格保留整个已声明研究范围内证券，特征资格仍按当时 context |
| 固定 16:00 与数据 15:00–17:00 更新冲突 | decision_hour 贯穿特征、模型、账户、发布和风格报告；新配置 18:00，旧省略值仍 16:00 |
| 未封存发布回执可能被单独改截止时间 | 回执必须与已封存预测/账户中的截止策略一致 |
| 统一研究入口把打分首日当成交首日 | 回放自动从首个打分日的下一交易日开始 |
| 每月重训 workspace 与持续账户混在一起 | account/registry 独立稳定路径，研究 workspace 分期；输入变化不覆盖既有产物 |
| 本机配置会导致工作树不干净、阻断研究 | 明确忽略 project.local.json / project.*.local.json；仍保留干净代码运行要求 |
| 金额单位倍乘可能制造浮点尾差 | 供应商十进制值先缩放再进入既有浮点存储；账本仍要求可精确表示的整数分/股 |
