# 假设成交的股数和现金核心

已新增一个独立的研究组件，用于以后把选股信号转换成可以核对的股数、费用与现金。
当前只验证人工构造的会计案例，没有读取历史行情、产生策略净值或接入真实委托。
原生命周期回测、执行规划和“已知费用组件不等于完整费用”的约定保持原样。

仓库原已有`quantity_cash.py`和25项测试，能按绑定的价格、日历与规则核算股数、T+1
及已声明佣金/印花税组件；它明确把完整现金和可成交性留为未知。本组件补的是带状态、
涨跌停、累计容量和完整**声明情景**的转移，不能将旧组件现金直接导入为完整可用资金。
两个对象的语义不同，后续适配器须显式转换并复用既有规则/日历资料；当前没有把新对象
接到历史路径，也没有撤掉旧组件的严格来源与时点校验。这次全套测试时补充识别了旧
算术组件，因此“回放还缺”不能表述成仓库此前完全没有股数核算。

`simulate_research_order`接收已有研究账本、一条目标股数请求和该股票当日的显式情景，
输出新的假设账本或阻断原因。输出与序列化结果均固定标记为研究用途、无执行授权、
不具备业绩认定资格。该函数不会自动加载用户费率、猜测板块规则或认证输入资料。

已经处理的内容：

- 不能卖出的股数保留；未完成的假设卖出不能产生买入资金。当日新买入股数锁到传入
  日历确认的下一交易日。卖出从可用持仓批次按取得日期消减，其他股票及锁定批次保留。
- 买入数量同时受现金、完整声明的建模费用和数量档位约束。最低佣金按本次假设委托
  汇总额计算，各费用组件明确舍入到分，不能把其他费用未知当0。
- 一般100股整倍数和最低200股、1股递增等只是可传入的规则形状。历史规则必须由后续
  验入器提供。零股全部退出要求整笔持仓都可卖且容量足够，不能用它绕过部分卖出限制。
  超过显式单笔数量上限直接报错，不自动拆成多笔。
- 收盘达到涨停不模拟买入、达到跌停不模拟卖出；不利滑点后的价格须在当天已知范围内。
  这些是保守的日线情景限制，日线仍不能证明实际排队或收盘竞价成交。
- 参与率同时限制前20日平均成交额、执行日成交额和股数。前20日资料不得晚于信号日；
  当日容量只在模拟执行阶段使用。同股同日的多次调用累计占用额度，买卖都计入，
  已消耗容量后不能变更该日情景来放宽额度。
- 股票身份、信号/执行日期、规则与费用适用区间、证据日期逐项核对。市场状态、日历、
  公司行为处理、价格上下限或费用组件未知就阻断，未知和明确不满足分别记录。

输入价格用整数分、数量用整数股；费用率与参与率用精确十进制数。费率、额外收费和
滑点必须明确填写，显式0只是该情景的声明，不是已核实市场事实。函数没有将旧费用
组件小计当完整费用使用。卖出可融资后续调用仅指已经完成的假设账本变动；模型没有
宣称真实收盘卖出款一定能用于同场竞价买入，后续逐日调度器还必须固定其成交顺序。

公司行为在本核心之前完成账本更新；“已处理”必须有独立证据，当前没有相应历史适配器。
分红税、未到账应收、送转到账及不可交易新增股数不能交给一个布尔值自行推断。
组件也不计算净值、隔夜价格变化、策略调仓或绩效，更不将被阻断持仓按0价值抹除。
当前返回部分数量后余量视为该次请求未执行；下一次请求需要新的标识并独立计费。

86项针对测试覆盖现金边界、最低佣金、逐组件舍入、可用批次、锁仓和部分卖出、零股、
容量共用、前视和错股资料、未知字段、非法数值、低精度环境及研究标记。现金约束的
二分搜索另用枚举合法股数核对。自审补齐了股票身份绑定、零成交容量的合理阻断和
同日情景指纹，避免错用另一股票行情或通过拆单重新获得容量。没有发生历史策略试跑。
