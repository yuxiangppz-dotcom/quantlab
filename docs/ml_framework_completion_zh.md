# 日频 ML 框架改造交付说明

## 范围与定位

目标是把日频机器学习选股形成可审计、可复现、可恢复的研究与前向模拟流程。
参考 Qlib 的研究/模型管理、LEAN/RQAlpha 的交易账户边界、NautilusTrader 的状态一致性、
Zipline 的输入快照及 vnpy.alpha 的本地工作流。没有合并或安装这些整套量化框架。

保留默认 Ridge / LightGBM、Alpha158、H10 标签、月度训练、缓冲换仓和现有股数现金内核。
既有已冻结研究、Daily/UI 和真实账户不自动迁移；新的默认研究入口是 `quantlab ml`。

## 本次改动

| 模块 | 实现 | 工程验收 |
|---|---|---|
| 执行 | 前日准入、预筹现金预算、无假定卖出名额、不回滚成交 | 阻卖、跳空、预筹现金与原调度语义回归 |
| 评估 | 分组成员在取标签前冻结，每组报告覆盖 | 缺标签不能改变原组成员 |
| 公司行动 | 登记日权益、应收股息、到账现金、送股锁定、整数拆股、旧单取消 | 应收不漏净值、不提前可买、权益不重复 |
| 状态与恢复 | 原子 JSON、每月模型封存、每天完整账户 checkpoint、输入绑定 resume | 中断恢复与完整运行同结果，输入变更拒绝 |
| 数据读取 | 按训练窗口、资格和必要证券读取；JSONL 按日索引 | 小窗口不全量物化历史；预算越界明确停止 |
| 数据时点 | 双时间事实选择、源修订和依赖 lineage、可选强制来源契约 | 新公布/修订内容不能回填旧决策 |
| 模型服务 | 注册与启用真实时间、保存模型独立推理、每日信号封存 | 推理与训练产物一致，不依赖标签 |
| 前向模拟 | 只使用当时已封存的有效前向信号，共用回放内核 | 晚补信号不能冒充前向信号 |
| 报告 | 共同区间基准、费用/滑点、风险暴露与覆盖、分块 IC 区间 | 手算指标和基准缺日拒绝 |
| 研究管理 | 预声明开发/保留区间、试验登记、单一最终规格 | 开发越界和换规格重用保留期拒绝 |

## 现在的完整运行逻辑

1. 来源数据和 PIT 上下文生成只读研究输入；feature 与 label 分开。
2. 标签按下一日收盘至第11日收盘计算；训练期只使用已经成熟的标签。
3. 每月独立训练/验证/预测，保存完整预处理、模型及来源，未完成月份可恢复重跑。
4. 决策读取实际现金/持仓，用缓冲排名、持有期和风险阈值形成目标。
5. 前日现金和仓位决定允许提交的买单；同次收盘的卖出不预先提供资金/名额。
6. 公司行动按权益快照变更股数、应收款和现金，取消不再适用的旧股数订单。
7. 下一交易日受费率、股数格、T+1、涨跌停、停牌和容量约束的模拟成交更新账户。
8. 保存完整状态和成交尝试；价格跳变导致的偏离如实记录，不改写已完成成交。
9. 比较共同区间基准、风险和成本，保留停止路径与所有试验记录。
10. 工程/数据验收后注册固定模型，每日只预测；封存真实当日信号，再以真实后续证据做 shadow。

## 边界

- 云端没有真实行情输入，不能交付真实 IC、净收益、容量或策略有效性证明。
- 历史股池/行业/ST/停牌/费率和数据公布时点仍需本地来源核验。
- 公司行动目前是明确支持类型的研究情景。持有期税、配股、非整数股、退市结算等不能猜测，
  有真实证据后由本地补适配并测试；空事件表也必须有覆盖来源。
- 日频收盘撮合是声明的研究假设，不能证明逐笔可成交。风格风险优化器不是本次默认组合，
  需先有合格暴露、协方差及目标定义；不把排序分数直接当预期收益率。
- 没有自动下载、Canonical 写入、券商下单或自动实盘晋级。
- 新命令没有自动接管旧 UI。详见操作文档和本地任务 prompt。

工程完成不等于所有真实输入已认证；真实输入已认证也不等于模型有净收益。
