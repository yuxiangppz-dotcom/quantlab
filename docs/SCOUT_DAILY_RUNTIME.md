# Scout 固定版本日常预测

## 使用

桌面安装目录内双击 **一键预测.cmd**。入口自动打开本机进度页，检查交易日、最新完成行情和连续窗口后启动任务；完成或校验失败都会打开已保存的报告。假日明确显示行情截至日、下一目标交易日。失败报告没有正式推荐。

同一版本、配置、日期、行情日与目标日使用同一持久任务键。并发点击、重开页面、已完成或失败后点击都复用已有任务；送达未知不会补发。异常退出的活跃任务须开发人员核查原始请求与状态，不能删除状态文件来重试。

数据过期在模型调用前停止。入口读取孤立行情副本，不自动改写原 canonical。下一交易日的数据可用后按既有数据更新流程增量更新孤立副本，再使用入口。

报告按重点核查、一般观察分组，只展示入选股票、选择理由、主要风险、失效条件，以及目标交易日和行情截至日。有具体停牌线索时保留该股交易状态。机会比较、来源覆盖、候选诊断、未入选名单不放在日常报告中。

完整 JSON、公开模型回复及证据保留；新运行另存 `audit_report.md` 和 `audit_report.html` 供开发审计。旧报告不覆盖；本机 `/report` 校验原报告 JSON 的 manifest 后生成简洁视图，不重新调用模型。

## 固定契约

| 边界 | 固定值 |
|---|---:|
| 模型 | DeepSeek Flash，低思考（冻结配置，给完整输出保留预算） |
| 初筛/深查数量 | 160 / 24，原策略保持 |
| 全程模型请求 | 最多 4 次：发现、调查、最终比较、任一阶段最多一次纠错 |
| 总 token | 1,200,000；未知用 UTF-8 输入字节加最大输出作保守预留 |
| 输出/请求 | 32,768 token |
| 输入/请求 | 180,000 字符；包含 schema/system 的保守上界 300,000 字节 |
| 超时 | 请求 180 秒；工作进程总 1,800 秒 |

本机请求日志在发送前保存精确 prompt、schema 与预留；接收后保存公开原始回复、计费 usage 或送达未知。没有传输重试。校验一次收集完整错误；唯一纠错携带原始研究输入、完整紧凑错误矩阵，以及当前分级/名次/比较对象/事实ID的有界摘要。错误上下文包含实际问题字段和合法比较对象；不追加整段回复历史。纠错自身仍须通过相同输入/总预算检查。

结构完整且错误可局部定位时，纠错仅返回授权JSON路径的补丁；程序只合并模型明确给出的替换，不改未报错的判断、名次或反证。合并后仍完整校验，未授权路径、重复路径或残余错误都失败，不再请求。截断或无法局部定位时，最多一次完整纠错，仍使用同一总预算。两种模式共享一次纠错额度。原始回复、模型补丁和合并结果分别保存哈希；报告的selection_origin明确标记组装来源，不能把程序组装结果称作一份独立原始模型回复。

专用研究输入移除全市场排除明细、本地快照路径及重复候选正文；完整原始审计仍在报告中。公告正文、反证、更新前摘要和覆盖缺口保留。统一事实表声明主体、指标、期间、原值和单位；本股、指定同行和行业引用同一表。模型用事实占位符判断，程序计算百分比/亿元并格式化，未知财务单位不转换。原始模型输出与显示文本独立保留和哈希。新模式不走旧中文句子数值逆推链路。

事实引用使用稳定短ID，主体、期间、数值与单位仍完整保留在事实矩阵；原长ID到短ID的映射留在审计报告中，不占模型输入。程序自动汇总正文及scale_fact_ids的引用，不要求模型重复列fact_ids。调查schema按本股绑定合法事件与规模事实；调查关系枚举和局部引用错误也可使用唯一一次定向补丁，其他字段保留。离线回放支持--stage investigation、--request与--response读取保存的真实调查请求/公开回复；短引用翻译只作用于离线副本，原文件不修改，fixture仍不是预测。

最终schema同样限定本股规模事实，行业统计须在正文作为行业背景引用。仅本股和声明同行的合法短证券代码视作身份，不当成数值；数量单位后的数字仍受事实引用校验。错误主体引用可定向修复相关字段，但有效引用及未报错决定必须保留，修复后仍重新核验主体与期间。

## 开发与发布

开发工作树可正常修复。日常服务从独立 Git 提交归档启动，不加载开发目录或临时配置；启动及结束核对已冻结的源码、配置、设置、锁文件和依赖版本。安装不复制凭据；仅启动时从既有受限环境文件加载。

1. 开发完成后执行全仓 pytest、Ruff、锁文件检查和 diff 检查。
2. 使用 scripts/scout_daily_replay.py 离线回放保存的真实 report.json。旧输出对新契约不兼容时完整拒绝；结构纠错 fixture 明确不是新预测，旧推理和反证不改写。
3. 提交、推送清洁版本；运行 scripts/scout_daily_install.py 安装该提交（WSL Ubuntu）。需明确 Git、孤立数据、持久状态、新桌面目录和发布根目录。
4. 使用桌面入口进行一次固定真实端到端验收。运行期间不改源码、提示、schema 或预算；失败保留，不临时补发。开发修复须形成另一个独立版本。

服务监听本机 127.0.0.1:8766，启动任务只接受页面的本机会话令牌。关闭页面不取消已经启动的后台工作。已暂停自动化不恢复；没有下单、模拟成交或净收益承诺。前瞻跟踪沿用报告冻结及既有 tracking/ranking 工具；未到目标交易日显示待观察。

仅升级报告展示时，安装器可用 `--prediction-release` 指向已验收的不可变预测版本。展示版本冻结该引擎 manifest 的 SHA256，并核对两者的隔离数据、输出及持久状态路径一致；引擎不允许再嵌套另一引擎。任务键、配置、预算及工作进程均使用原预测版本，工作进程从该版本自己的 Python 环境启动。同日重复点击复用原任务，不因展示升级增加一次付费预测。`/state` 分别记录预测 `version` 和 `presentation_version`；桌面启动器核对展示版本。新预测引擎仍须按上述完整流程另行验收。

## 验收边界

测试通过、结构 fixture 通过、真实流程通过和选股赚钱是四件分别记录的事实。工程交付只以固定真实运行、完整校验、报告保存/打开、重复点击复用为验收；准确率与净收益需独立前瞻观察，不由本次交付推断。
