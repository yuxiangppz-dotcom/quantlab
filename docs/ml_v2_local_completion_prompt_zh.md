# 交给本地 Codex 的执行 prompt

复制下面整段到拥有 QuantLab 本地仓库及行情数据的 Codex 会话执行。
云端已经实现代码主流程；下面重点是本地证据绑定、集成验证和仍需数据的适配。

---

你正在修改我的 QuantLab 项目。我关心研究框架正确、可复现、合理，不以优化某条 -98% 曲线为目标。
请先阅读 AGENTS.md、docs/ml_daily_v2_zh.md、config/ml_daily_v2.json、
src/quantlab/research/ml/ 和 quantity_kernel.py / quantity_scheduler.py。
确认已有云端 ML v2 改造已在当前分支，保护用户未提交改动，确认没有其他代理同时写目录。

沿用已有实现继续完成本地工作，不要重新另造一套训练/回测框架，不要改旧冻结实验的结果定义。
你可以检查本地现有数据、编写/修复适配代码、生成隔离的 research/experiment 产物并运行测试和训练。
本任务不要求调用供应商、写 Canonical、修改账户、提交交易或自动晋级策略；
遇到此类需求，先给出精确缺项和最小获取范围，不要用猜测填 true / 0。

按以下顺序完整执行，能做的直接做；真实缺少的数据/权限才列为阻塞。

1. **定位来源与验证运行环境**
   - 找到原 Alpha158 历史 staging 的 inventory、plan、raw/feature receipts 和 usable_features 分区。
   - 验证 seal 和 SHA；审计分区重叠/遗漏、trade_date/instrument_id 唯一性、单位、复权与退市身份。
   - `uv sync --frozen --extra research --extra qlib`；运行全量 pytest、ruff、diff --check。
   - 列出实际历史起止、共同股票池、市场日历、内存/磁盘预算。默认训练需要 1008 个历史交易日。
     历史不足时推迟首个预测日，不要静默降成更短窗口；如确需改窗口，另存配置并说明理由。

2. **完成历史 PIT 上下文适配器，不能人工制造可用性**
   - 产出 `pit_context.parquet`，列恰好是 trade_date、instrument_id、eligible、industry、
     feature_available_at；覆盖退出后仍可能持有的证券，不可只保留今天仍上市的名单。
   - SH/SZ A 股；按历史上市/退市日期、当时可知 ST 状态、历史身份和明确流动性规则决定资格。
     起点：上市 >=120 个市场交易日；过去 20 日平均成交额 >=5000 万元；规则仅用 t 日已知信息。
   - 行业使用当时有效分类；如行业历史缺失，保持 unknown 并指出来源缺口，不能用今天的行业冒充。
   - feature_available_at 必须带时区、来源清楚。区别供应商历史字段可用性与今天导出的时间，
     回溯重建假设必须明确登记为假设，不能宣称当年真实前向产物。
   - 结合现有数据访问/封存组件写成可复现的只读适配脚本，补数据缺口/历史身份合成测试。
   - 调用 `quantlab ml export-history`，生成新的隔离输入包；保留所有来源指纹与覆盖报告。
   - `quantlab ml check` 必须通过；若全部数据超过矩阵预算，先冻结合理 PIT 流动性股票池，
     或实现可验证的按月/按分区读取优化，不能在背后随机删样本。

3. **绑定真实交易情景；公司行动是必须核验的接缝**
   - 生成每个执行交易日的 `ResearchDay` JSONL 和首个决策日 initial_marks JSON，走现有 decoder。
   - 原始价格用分、成交量用股、成交额用分；复权价只用于特征/标签，绝不能用于股数成交。
   - 涨跌停/停牌/板块/股数规则必须按历史生效日绑定，未知保持 null。
   - commission、最低佣金、印花税、其他费用按生效日区分；核对已有 research_user_costs_v1.json
     报价是否完整/已证实；不能把未知其他费默认归零。
   - 冻结滑点 5/10/20 bps 三个独立情景，参与率先取已知 ADV 和当日容量的 0.5%，
     标注是研究假设，不伪造真实撮合。容量预算窗口必须不晚于信号日。
   - 接入并测试已有 corporate/dividend/recipient 组件，对现金分红、送转、拆并、退市结算，
     按已核验生效时间更新股数/现金。当前 ML 适配层没有自动处理这些事件；
     **不能只把 corporate_processing_complete 设 true 就宣布支持**。
     需要改进逐日 adapter 与现有权益账本接口，保持资金和股数守恒，禁止重复发放权益。
   - 如果证据缺失，运行到首个无法支持的日期并保留持仓、现金、停止原因，不截掉坏股票继续跑。
   - 增加真实样本抽查：普通交易、涨停买不到、跌停卖不出、T+1、停牌缺价、分红除权、退市各一例；
     无真实样本的类别明确记为未验收。

4. **冻结一次基线实验，先证实一致性**
   - 默认 rank label H=10、Ridge / LightGBM、月度 882+126 日窗口、5 日调仓/持仓缓冲。
   - 新目录预登记输入/配置/代码/资源预算后训练；无需反复试 seed 或大范围搜索参数。
   - 用相同输出打分分别回放 5万/20万/100万元、三个成本情景；不要线性缩放 normalized NAV。
   - 在共同有效区间比较模型；成本/数据不同或路径停止导致区间不同的结果不可直接混排。
   - 输出日/年 rank IC、非年化 ICIR、头部分层与覆盖、打分稳定性、实际换手、费用、
     现金占比、目标/实际仓位差异、拒绝/部分成交、日净值、最大回撤、Sharpe 与容量约束触发数。
   - 增加“同一成交序列费用反事实”或明确定义的零成本控制，区分模型收益和费用拖累；
     反事实若改变成交股数，必须标为不同路径，不要称精确费用差。
   - 增加同期可实现的简单基准，并给出行业/市值/波动暴露；没有基准价格/分类就报告缺口。

5. **在验证后才扩展模型/特征**
   - Ridge 与 LGB 结果先决定后续研究价值；不要因 LGB 名字更复杂就默认使用。
   - 至多增加一组预登记对照：H=5 或 binary 或 LambdaRank，不同时大规模搜索。
   - 基本面要公告日/实际可用时刻与修订历史，先加入可验证的估值、盈利、质量、成长少量因子。
     行业/市值残差化必须只用当日可用暴露、保留原始收益评估；不删掉真实极端亏损。
   - 尚无稳定净收益证据时，不引入 Transformer/LLM、复杂优化器或自动实盘。

6. **最终验收与交付**
   - `uv run pytest`、`uv run ruff check .`、`git diff --check` 全部执行；
     `QUANTLAB_TEST_OPTIONAL_RESEARCH=1 uv run --extra research --extra qlib pytest -q
     tests/research/test_optional_runtime.py tests/research/test_ml_v2.py` 验证真实可选运行时。
   - 报告起止 HEAD、改动文件、测试结果、真实数据覆盖、工程缺口、是否具备继续前向观察条件。
   - 代码/配置/文档提交到独立分支，生成实验数据不提交 Git，不改旧实验凭证。
   - 输出中文验收报告和剩余最小阻塞列表。没有证据就明确未知，不填造收益或“业界已达标”。
   - 即使历史结果好，也只接入独立 forward-shadow 观察入口；不把 retrospective 实验
     自动注册为可执行策略，不修改现有真实账户。

---

本地仍可能缺少的数据：历史行业、ST/停牌/涨跌停、完整公司行动、确切费用条款、
退市结算和部分交易规则。代码可以实现适配接口，但这些事实本身不能由云端编造。
