不要仅给计划，不围绕已有 -98% 曲线调参，不引入多个框架重写。

先读取 AGENTS.md、README、docs/project_pipeline_zh.md、config/project.example.json、
config/ml_daily_v2.json，以及 pipeline/、data/transport.py、research/ml/。核实 PR #189
（分支 codex/ml-framework-v2-20260916）的最新状态：未合并从最新 PR head 新建工作树；已合并
从包含这些提交的主分支开始。保护本地未提交工作，确认没有其他 Agent 同写，不强推。

授权你只读盘点现有数据，修复代码，生成隔离研究产物，训练、回放、模拟账户、测试和提交推送。
先使用现有数据；真实供应商请求、Canonical 的接管/写入、操作系统定时器安装须依据我在当前
本地会话明确授权的范围执行，不擅自扩大下载或数据改写。无论如何不下真实订单、不改真实账户、
不提交 token/行情/模型/机器路径。需要额外权限时先完成可审查的配置和计划，再说明精确缺项。

1. 安装锁定环境：`uv sync --frozen --extra research --extra qlib`。复制 project 示例为本地配置，
   填入实际路径；workspace 用本次日期命名，account、registry 采用稳定路径。
   执行 `quantlab pipeline --project ... plan`，不凭空声称数据已完整。
2. 盘点 daily/adj_factor/daily_basic/index/trade_cal/证券身份、ST/停牌/涨跌停、行业、公司行动。
   检查历史漏日、重复、单位、前复权/原始价、代码变更和退市。确认当前股票名单没有代替历史股票池。
   按 `project_pipeline_zh.md` 准备四份来源输入：context、availability、execution_policy、corporate_actions。
   它们必须有 source_id、版本和真实时点依据；财务报告期不是公告日，今天下载时间不是历史发布时间。
   未知项保持 unknown，并给出缺数据的具体接口/字段/日期范围。
3. 复用已写好的 pipeline 同步与适配。授权后运行 sync；旧 Canonical 首次接管先核对再用
   --adopt-existing；已有完成回执不能原地刷新。抽查原始响应和规范化数据，确认响应限额、权限
   和空返回语义。不能通过删回执/改 hash“修复”坏数据，也不能用空公司行动掩盖未知事件。
4. 复用 build 自动生成特征契约、lineage 和价格；不能再另写一套每日 Alpha158。
   先检查机器内存/磁盘、lookback 和 882+126 训练历史。不足时推迟首个预测日，不静默缩窗口。
   用有历史资格的明确小范围先做验收，再扩范围，不能按结果剔除亏损/退市股票。
5. 复用 train/replay/report。默认 18:00 决策，下一日收盘执行，H=10 rank 标签，Ridge 对照、
   LightGBM、低换手缓冲组合。训练输入变化就新建 workspace，不复用旧训练输出冒充同一实验。
   2023–2026 已观察过，不称未触碰最终测试集；预先登记后续比较范围和少量参数。
6. 对照真实样本检查：普通成交、最低佣金、涨停买不到、跌停卖不出、T+1、停牌估值、分红权益/
   除息/到账、送股可卖日和身份变更。费用按生效区间，整数分与股数口径一致；应收款不能当现金。
   配股、零碎股、持有期税、特殊退市结算缺真实规则时明确阻断；有证据再适配并补回归测试。
   日期和费用缺失不能填成有利值。市场文件和基准由适配器生成，不再手工拼接。
7. 报告 IC/rank IC、分层、净收益、换手、费用、回撤、现金和拒单；统一基准及共同区间。
   至少用预登记资本和成本情景重跑，不能按比例放大 NAV；零成本加回仅是归因，不等于重新撮合。
   策略无效时如实拒绝，不需要通过无限调参获得好看的结果。
8. 在持续 registry 登记已通过来源和研究验收的模型，明确真实启用时间；不能倒填过去。
   从空仓初始化隔离 paper account。运行 `daily --as-of 日期 --sync --execute`（已有同步可省略后两项），
   按交易日连续推进。前一日封存订单先结算，再形成下一日决策；同日重跑不能重复成交。
   过截止时间只能补账，不能把晚生成信号说成前向。缺模型/过期必须显式显示。
9. 准备 WSL2/Linux 定时器（建议 17:15 后、18:00 前有限重试），记录非零退出码、数据日期、
   模型年龄、账户停滞、磁盘空间；安装前按本机会话授权执行。先演练断网、半写入、中断恢复、
   重复日、漏日、坏分区、模型过期、输入改变、磁盘不足。备份 raw/Canonical/receipts/account/registry，
   在隔离目录验证恢复，不能仅声称“做了备份”。按月新 workspace 重训，账户和 registry 不重置。
10. 跑完整测试、Ruff、diff检查，以及 `QUANTLAB_TEST_OPTIONAL_RESEARCH=1` 的 pipeline 和研究测试。
    修复真实缺陷后再 review。持续观察至少 20 个交易日；无法在本次完成的天数列待验收，不能伪造。
    最后提交代码/文档并提供 PR，报告起止 HEAD、命令、输入范围、资源与测试结果、真实数据通过项、
    未通过项、每日运行方法和恢复方法。严禁把合成测试通过写成策略已有效或可以实盘。
