**一、环境与已有数据盘点**

1. `uv sync --frozen --extra research`（仅旧 Qlib 复现/可选测试再加 `--extra qlib`），运行 `uv run quantlab ml --help`。
2. 查找本地已有 daily、adj_factor、trade_cal、security_history、daily_basic、historical universe、
   ST/停复牌/涨跌停、行业、公司行动、基准指数，以及已封存 Alpha158 history 的 inventory/receipts。
   不假定目录位置或宣称数据齐全。审计日期范围、唯一键、单位、漏日、证券身份变更、退市记录。
3. 核对原始成交价与复权研究价的区别。原始价/金额进入账本需转成整数分，成交量需为股；
   TuShare 接口单位分别按实际字段来源核验，不一律乘同一个系数。
4. 记录 WSL2 的可用内存、磁盘与运行预算。我本地机器可能只有 16GB 内存，先用预先声明的
   历史可投资股票池验证链路，不把当前成分股套用整个历史。已有数据足够时可先用约 300–500
   只历史 PIT 成分组成的范围，随后再扩大；不能静默随机抽样或排除亏损/退市股票。
5. 默认训练要求 882+126 个历史交易日，并需要标签尾部/回放前后日历 padding。历史不足时
   推迟首个预测日；改窗口必须新建配置并记录理由。

**二、构建有出处的数据契约**

1. 复用已有特征历史和 data/research 组件，编写可重复的只读适配脚本。已有封存历史可用
   `quantlab ml export-history`，它需要恰好五列的 PIT context：
   trade_date、instrument_id、eligible、industry、feature_available_at。
2. 股票资格、行业和身份映射均按当时历史处理。必须保留仍可能持有的已退出股票的元数据。
   不知道历史 ST、行业或退市结算时保持 unknown，不当作正常股票或已卖出。
3. 特征来源需区分 effective_at（经济生效/所属期）、known_at（市场当时可知）、revision_id。
   财报使用公告/修订时间，不用报告期末当公布日。参考 ml/pit.py 的 asof_facts。
   回溯生成的特征可以用于有明确假设的历史研究，不能声称当年真实前向生成。
4. 创建 `feature_contract.json`，feature_dependencies 必须恰好覆盖特征 allowlist；
   创建 `pit_lineage.parquet`，列为 trade_date、instrument_id、source_id、known_at、effective_at、revision_id。
   每个日期/证券/来源一条版本收据，源数据可用时刻不能晚于 feature_available_at。
   由真实来源形成收据，不统一填一个虚构的早期时间。窗口依赖应登记最晚可知源版本。
5. 用 `prepare-inputs` 将特征、价格、日历、allowlist、来源说明和 lineage 封存为新包。
   不给已封存包原地补列或换文件。执行 `check --require-lineage`，说明结构验收与来源真实性的区别。
6. 对历史股票池、行业变更、公告后修订、代码变更、缺标签端点各写最小回归例子。

**三、绑定市场交易和公司行动，不能只设置 true**

1. 生成逐日 market_days.jsonl 和首个决策日 initial_marks.json，结构见 ml/io.py 与文档。
   必须有逐日原始估值、交易可行性、板块/生效日股数规则、涨跌停/停牌、过去20日容量窗口、
   当日成交量/额、参与率和完整费用。未知保留 null，不补零费用或可交易状态。
2. 费用从已有用户报价及历史条款核验：佣金、最低佣金、买卖税费、其他费用分别建生效区间。
   滑点和参与率是研究假设；先登记 5/10/20 bps 成本情景及 0.5% 参与率，再统一运行，不挑最好结果。
3. 核实 `prior20_asof <= signal_date`，当日容量仅限制执行，不反过来影响前日选股。
   满持仓换名采用保守两阶段方式：不使用同次收盘尚未确认的卖出资金/名额，可能暂时多持现金。
   不恢复旧的“先成交，再撤买单重跑”逻辑。跳空超限要报告并在下一决策处理。
4. 创建 corporate_actions.json，提供有出处的 coverage(start,end,source_id) 和 events。
   云端已实现 record-date entitlement、现金股息应收/到账、送股可卖日、整数比例拆股，
   使用 ml/corporate.py。你需要把真实事件映射到这些接口并核对，而不是重写账本。
5. 现金事件 net_cash_per_share_fen 是显式净现金情景。A 股持有期相关税务不能用统一净额
   冒充已认证；如已有证据能支持，扩展税款/清算事件与账本并写测试，否则准确列为阻塞。
   非整数股、配股、退市清算及其估值不能从普通分红公式推断；有实际规则和样本才实现适配。
6. 不能用空 events 隐瞒不知道的公司行动；不能只把 corporate_processing_complete 设 true。
   没有事件也需有来源和区间覆盖证明。证据不足则保留停止日和完整账户状态，不删除坏路径。
7. 真实样本至少抽查：普通成交、最低佣金、涨停买不到、跌停卖不出、T+1、停牌估值、
   分红除息/到账、送股及可卖日、证券身份变更。没有真实样本的类别明确记为未验收。

**四、完成一套预登记基线实验与报告**

1. 先登记研究假设、开发期和最终验证范围；已经观察过的 2023–2026 不再称 untouched holdout。
   `init-study` / `train --study` 用于约束后续试验，不会抹去过去看过数据的事实。
2. 第一轮只使用默认 H=10 rank 标签、Ridge 与 LightGBM、月度训练、5日调仓和缓冲持仓。
   配置、来源与代码保持一致后 `train`；进程中断加 `--resume`，改变数据/代码/参数则新建实验。
3. 打分日期是决策日，replay 的日期是下一交易日执行日；首日不能相同。使用同一份打分，
   独立回放 5万/20万/100万元以及预声明的三个成本情景。不要按比例放大单位 NAV。
4. 检查 ledger/attempts/positions/decisions/sessions/terminal：资金与股数守恒，应收款非可用现金，
   失败卖单保留股数，不能重复记公司行动，实际成交和目标仓位有明确差异记录。
5. 绑定同期指数或可解释的股票池基准，输出 benchmark.parquet(session,benchmark_return)。
   明确价格/全收益口径，不拿10日标签当每日收益，不删除缺失基准对应的策略亏损日。
   如加入等权股票池基准，成员按前一日 PIT 信息确定，并区分参考收益与可交易含成本组合。
6. 如有可靠来源，生成带 available_at 的历史市值/波动/beta等风格暴露，使用 `report --exposures`。
   输出同期收益、相对净值、风险、IC及覆盖、分块区间、换手、现金、费用、滑点、拒单和部分成交。
   报告现有列未汇总的约束触发次数时，从 attempts 明确计算，不能把 TopK 名单变化当成换手。
7. `report` 的同成交成本加回是归因，不是重新撮合的零成本策略。成本变化会改变资金与成交时，
   必须单独回放并标明路径变化。不同停止日期先比较共同完成区间，同时保留完整停止原因。
8. 按年份/市场阶段补充稳定性分析，记录尝试总数。若比较新目标，只预登记少量对照，
   例如 binary 或 LambdaRank；不要同时搜索所有窗口、因子、种子和参数。

**五、接通真实每日模拟服务**

1. 使用 `docs/ml_service_zh.md` 已实现的 init-service/run-day/service-state/service-report。
   不用旧顶层 shadow；`ml shadow` 只用于封存分数的情景对照，不冒充当时已封存的组合决策。
2. 编写本地只读日快照适配器，产出 features/calendar/market/corporate_actions 及 manifest。
   与历史训练共用特征公式、顺序、单位和可用时间处理；契约 SHA256 必须匹配注册模型与服务。
   保留所持股票的标价与历史上下文，已知公司行动从登记日追踪到到账日。
   每日输入约定详见操作手册，数据来源/available_at 不得为了满足16:00门槛而伪造。
3. 真实样本核验后注册模型、显式 activate。从当前真实日期初始化模拟账户；不导入真实账户资金。
   先人工执行一个完整日任务并核验订单/实际持仓/现金/应收/费用，再启用定时任务。
4. 在用户的 WSL2 上创建本地 systemd user timer 或适合其环境的计划任务。先探测系统支持，
   不假定路径、不写死用户名、不把 token 写入脚本。用户已授权本任务安装这些仅模拟用途的本地定时任务；
   缺数据时保留为 disabled 并说明原因。建议交易日15:45开始预检/适配，16:00前完成决策发布；
   实际供应商到达时间不满足时保持阻断，不倒填时间。
5. 调度顺序：交易日判断 → 源数据已有覆盖/新鲜度核验 → 构建日快照 → 模型有效期检查 → run-day → 状态核验。
   run-day 返回2表示没有合格前向决策，非零失败都要写日志并明确报警。仅用本地日志/桌面通知，
   不擅自向他人发送消息。WSL/电脑休眠或关机不会保证任务运行，要记录 missed sessions 并按序补记。
6. 每月准备新模型（复用 train，不日更重训），验证后显式注册启用；45自然日默认年龄上限不静默放宽。
   模型更新任务失败不继续无限使用旧模型。不得按单一IC门槛自动晋级。
7. 验证连续至少5个真实交易日后交付运行日志；若当前时间不足，只报告已实际观察天数和剩余观察计划，
   不伪造未来记录。验证重跑不重复记账、漏日补跑不补造订单、暂停仍处理此前订单及估值、缺费用不提交账户。
8. UI 首页 ML 工作台应展示新账户，旧实验在历史研究。核对服务新鲜度、现金、实际持仓、
   封存目标、成交/拒单、费用和风险；执行 service-report，基准缺日必须拒绝，不删掉坏日。
9. 将研究产物、模型注册库、日账户和原始凭据纳入本地增量备份，演练一次从备份恢复后校验。
   禁止删除唯一来源或覆盖已完成日；失效训练/回放使用新输出路径，原失败证据保留。
